# Infinity Xray

Серверная сборка Xray: keepalive для тихих соединений,
governor HTTP/2 XHTTP, диагностика mux и дополнительные проверки конфигурации.
Работает со стандартными клиентами. В основе — официальный XTLS/Xray-core;
Infinity Xray имеет собственную версию, не подменяющую номер базы Xray.

**Текущая версия: `0.1.0-rc.1`. Это кандидат релиза.** Объединённая сборка требует
полного Linux-прогона и проверки итогового Docker-образа перед использованием
на рабочих нодах. Сценарии ничего не устанавливают и не публикуют автоматически.

Настройки базы и SHA256 единого патча находятся в `release.json`.

`infinity-xray.patch`. Репозиторий самодостаточен для сборки.
Закреплённые версии не означают актуальность базы относительно новых upstream-релизов.

## Что входит

| Компонент | Поведение и ограничения |
|---|---|
| Hysteria keepalive | Сервер отправляет QUIC keepalive, в том числе без прикладного трафика. Таймауты мёртвого клиента остаются механизмом QUIC. |
| Mux keepalive | При отсутствии записей клиенту отправляется пустой стандартный кадр Mux.Cool. Это помогает сохранять тихий downlink через CDN; нужен mux на клиенте. |
| Mux поверх XHTTP | Снят серверный запрет mux для XHTTP. Для MASQUE прежнее ограничение сохранено. |
| TCP-only Mux.Cool | UDP к служебному имени `v1.mux.cool` проходит обычную маршрутизацию вместо TCP mux-обработчика. |
| REALITY validation | Ошибочные серверные ключи и short ID из protobuf/API отклоняются до запуска слушателя. |
| HTTP/2 governor | Управляет серверным flow control XHTTP. Может уменьшать задержки соседних запросов под нагрузкой; требует больше CPU и может уступать полосу конкурирующему TCP. |
| Ограниченная остановка | До 7 секунд на Close и до 1 секунды на сообщение об ошибке. Зависший Start не покрывается. |
| icstats | Агрегированные счётчики Hysteria/mux и длительности записей mux, без содержимого трафика. |

**Принудительный отзыв VLESS-пользователей не включён.** Remnawave Node 3.4.4
делает remove/add даже при синхронизации неизменного пользователя. Патч RemoveUser
в таком случае обрывает действующие соединения. Обычное поведение базы сохранено.
Изменения клиентского governor, политик ML-KEM и другие транспорты стороннего
форка также не включены. Происхождение кода перечислено в [NOTICE.md](NOTICE.md).

## Сборка

Нужны Python 3.11+, git и Go с поддержкой автоматической загрузки toolchain.
Go 1.27.3 загружается по необходимости. Для образа дополнительно нужен Docker
с Linux Engine. Первая сборка обращается к GitHub и серверам модулей Go.

Linux:

```bash
bash build.sh
# С расширенными тестами governor:
bash build.sh --full-checks
# Бинарник и образ Remnawave:
bash build.sh image
```

Windows PowerShell:

```powershell
python build.py build
python build.py build --target windows/amd64
# Или оболочка PowerShell с теми же параметрами:
.\build.ps1 build
```

По умолчанию собирается Linux/amd64, проверки Go выполняются на ОС сборки.
Для полноценной проверки серверного поведения предпочтителен Linux.
Внешние `GOOS`, `GOARCH` и `GOFLAGS` не переносятся в проверки.

Выходные файлы Linux находятся в `out/0.1.0-rc.1/linux-amd64/`:

- `xray` — бинарник;
- `SHA256SUMS` — его SHA256;
- `build-info.json` — версия Infinity Xray, база, патч, toolchain, build tags и хеш бинарника.

Версия в выводе `xray version` выглядит так:

```text
Xray 26.10.31 (...) Infinity-Xray/v0.1.0-rc.1 (go1.27.3 linux/amd64)
```

Исходники создаются в новом `.work/infinity-xray-*/source`. Старые каталоги
не удаляются. Повторная сборка той же версии заменяет артефакты в её каталоге;
для опубликованных версий это запрещено правилами выпуска ниже.

Для разработки можно подготовить исходники без сборки или использовать локальный
git-клон базы, содержащий закреплённый commit:

```bash
python3 build.py prepare
python3 build.py build --source-cache /path/to/Xray-core
```

Локальный клон проверяется по commit, его незакоммиченные изменения не копируются.
Байтовая воспроизводимость всех окружений отдельно не подтверждена.

Для изменения объединённого патча используйте подготовленное дерево исходников,
внесите правки и сформируйте diff относительно закреплённого HEAD. В Bash:

```bash
git -C /path/to/prepared/source add -N .
git -C /path/to/prepared/source diff --binary HEAD > infinity-xray.patch
```

`add -N` нужен, чтобы новые файлы тоже попали в патч. Сохраните LF и UTF-8;
не используйте для этого обычное перенаправление PowerShell 5.1, создающее UTF-16.
Обновите `patch.sha256` в `release.json` по SHA256 новых байтов. Список `components`
описывает первоначальное объединение; новые изменения фиксируйте в CHANGELOG
и NOTICE с их происхождением. После смены базы обновите её tag и полный commit.

## Проверки и границы достоверности

Каждая сборка выполняет vet и тесты icstats, mux, inbound, REALITY и Hysteria,
проверку парсера h2Flow и профильные тесты остановки. В проверке `infra/conf`
vet отключён из-за прежних предупреждений по protobuf с mutex.
Unix-процессные тесты остановки на Windows пропускаются самим тестовым набором.

`--full-checks` добавляет профильные governor-тесты с лимитом 8 минут.
Быстрая сборка сама по себе не подтверждает работу governor под нагрузкой.
Проверки инструмента выпуска:

```bash
python3 -m unittest -q test_build.py
```

До объединения отдельные компоненты проходили локальные проверки целостности
XHTTP/Hysteria, 120 секунд простоя и netem-сценарии. Исторически governor уменьшал
p95 соседних запросов при скачивании/RTT 50 мс с 2411 до 309 мс, но при конкурирующем
TCP получал 34,2 вместо 84,9 Мбит/с; CPU также вырос. Это исторические результаты
другой сборки на локальном Linux-стенде, не обещание производительности этого RC.

Для новой диагностики mux тесты прошли, бинарник Linux был собран. Расширенные
governor-тесты на Windows не уложились в лимиты 90/180 секунд. Нагрузочная проверка,
Linux race detector и сборка/запуск Docker-образа объединённого RC пока не подтверждены.

Для `0.1.0-rc.1` отдельно проверены применение объединённого патча к чистой базе,
стандартные vet/тесты сценария сборки, парсер h2Flow и сборка Linux/amd64 на
Windows с Go 1.27.3. Процессные Unix-тесты остановки на этой ОС не запускались.

## Настройки

| Переменная | По умолчанию | Значение |
|---|---|---|
| `XRAY_IC_QUIC_KEEPALIVE` | `10` | Интервал серверного QUIC keepalive в секундах; ≤0 отключает. |
| `XRAY_IC_MUX_KEEPALIVE` | `5` | Интервал тишины перед mux keepalive в секундах; ≤0 отключает. |
| `XRAY_IC_STATS` | `60` | Интервал сводки icstats в секундах; ≤0 отключает только публикацию сводки. |
| `XRAY_XHTTP_FLOW` | В Docker `on`; для отдельного бинарника выключен | Включение серверного governor при старте. |

Явный `xhttpSettings.extra.h2Flow.enabled` имеет приоритет над `XRAY_XHTTP_FLOW`:

```json
{
  "xhttpSettings": {
    "extra": {
      "h2Flow": { "enabled": true }
    }
  }
}
```

Это фрагмент настроек транспорта, а не полный конфиг сервера. Изменения окружения
применяются при старте процесса; динамическая перезагрузка не добавлена.

В сводке `[icstats]` секция `mux_write` содержит:

- `active` — незавершённые записи в нижележащий writer;
- `total` — завершённые попытки, включая ошибки;
- `slow` — завершённые записи длительностью ≥1 секунды;
- `err` — ошибки записи;
- `max_ms` — максимальная длительность завершённой записи.

Счётчики и максимум накопительные с запуска, а не за последний интервал.
Учитываются данные и keepalive всех mux-транспортов. Незавершённая запись
не обязательно зависла, а ошибка сама по себе не объясняет причину обрыва.
Время включает ожидание внутри writer, не только передачу по сети.
Соединения без mux эта диагностика не измеряет. Другие штатные логи Xray
регулируются обычной конфигурацией логирования.

## Docker и установка на ноду

Команда `python3 build.py image` создаёт локальный образ
`infinity-xray:0.1.0-rc.1-node3.4.4` поверх `remnawave/node:3.4.4`.
Она не отправляет образ в registry и не меняет работающие контейнеры.
Бинарник заменяет `/usr/local/bin/xray`; штатный `rw-core` использует его.
Тег базового Docker-образа закреплён, digest пока не закреплён.

Перед пробной установкой сохраните прежний compose и точный ID старого образа.
В существующем сервисе Remnawave Node меняется только `image`; его порты,
секрет подключения к панели, тома и остальные настройки остаются локальными.
Перезапуск контейнера оборвёт текущие соединения. После запуска проверьте
`xray version`, фактическое окружение процесса, подключение панели, логи и
реальный клиентский трафик. Для отката верните прежний образ и пересоздайте сервис.

Новый RC не заменяет ранее установленные образы автоматически. Проверка
передачи переменных через конкретный сервис s6/rw-core обязательна при тесте образа.
В исходниках Node `3.4.4` сервис xray использует `with-contenv`; фактический
Docker-образ ещё не проверялся.

## Версионирование и выпуск

Источник версии — файл `VERSION`, формат SemVer:

- `MAJOR` — несовместимые изменения конфигурации или поведения;
- `MINOR` — новая совместимая возможность либо обновление базы, требующее проверки;
- `PATCH` — совместимое исправление;
- `-rc.N` — кандидат релиза, ещё не признанный стабильным.

Тег git — `v0.1.0-rc.1`. Версия официального Xray хранится отдельно в `release.json`.
Docker-тег дополнительно включает версию Node; переиспользовать опубликованный
номер для других патчей или базы нельзя. Новый патч означает новый номер версии.

Порядок выпуска:

1. Обновить единый патч, его SHA256 и сведения о происхождении в `release.json`.
2. Обновить `VERSION`, README и CHANGELOG.
3. Выполнить тесты выпуска, полный Linux/governor-прогон, race-проверки и
   испытания XHTTP/Hysteria/mux, простоя, нагрузки, остановки и Docker-окружения.
4. Сохранить commit, исходный комплект, бинарник, `SHA256SUMS` и `build-info.json`.
5. Создать неизменяемый тег `v<версия>` и публикацию с результатами проверок.
   До завершения проверок отмечать выпуск как prerelease.

Подготовка отдельного каталога для GitHub:

```bash
python3 build.py export --destination /path/to/new/infinity-xray
```

Копируются только явно перечисленные публичные файлы. История монорепозитория,
внутренние документы, лабораторные адреса, конфиги нод, ключи, БД и `.work/out`
не включаются. Каталог назначения должен быть новым. Экспорт не создаёт
репозиторий GitHub и ничего не отправляет наружу.
