# Infinity Xray 0.2.0-rc.3: работа на ноде

Дата: 2026-11-10/11. База: Xray-core v26.11.9, образ на Remnawave Node 3.4.5.
Нода DE-1, клиенты идут через L4-реле (haproxy по SNI для TCP, DNAT для UDP).
Адреса, домены и имена хостеров в отчёте убраны.

## Итог

| Что | Результат |
|---|---|
| Стабильность | 0 рестартов контейнера, ошибок ядра в логах нет |
| Нагрузка | около 32% одного ядра CPU при ~130 Мбит/с |
| Governor (`XRAY_XHTTP_FLOW`) на XHTTP + REALITY | Включается: счётчик срабатываний 3 → 20 под живыми клиентами |
| Метрики Prometheus и icstats | Работают, слушают только loopback |
| Открытые входы | XHTTP + REALITY tcp/443 и Hysteria2 udp/443, доступ только с реле |

Регрессий относительно rc.1 не замечено. Сравнения A/B с прошлой версией
на той же ноде под одинаковой нагрузкой нет, поэтому «быстрее» или «экономнее»
отчёт не утверждает.

## Проблема с первым пингом через реле

Симптом: через реле первый пинг Hysteria около 5000 мс, XHTTP не отвечает.
Та же сборка на ноде без реле работала стабильно.

Причина не в ядре. Все соединения, дошедшие до ноды, ядро обработало штатно.
Потери были на участке реле → нода: при ~44 новых соединениях в секунду с одного
адреса часть пакетов уходила с реле и не доходила до ноды, а такой 4-кортеж
оставался «чёрной дырой» несколько минут. Ретрансмиты хвоста ClientHello
оставляли около 1200 соединений в LAST-ACK / FIN-WAIT-1.

Исключены проверкой: SNI, размер и fingerprint ClientHello, half-close,
троттлинг на 16 КБ, чётность порта, сама нода, антисканер и лимитер на реле
(tcpdump видит пакеты до nftables; отключение не помогло).

Что помогло (изменения на реле, ядро не менялось):

- пул исходящих портов к ноде 20000–29999;
- `timeout connect 1s` и `retries 5` в haproxy;
- fingerprint клиента chrome → firefox;
- снято правило, отбрасывавшее чётные исходящие порты.

После: 160–170 SYN за 15 с, 0–1 ретрансмит, около половины с чётных портов.

## Не проверено

- Поведение реле под вечерней нагрузкой: пул в 10 тыс. портов прокручивается
  примерно за 15 минут.
- A/B rc.1 против rc.3 на одной ноде: CPU на Мбит/с, время до первого байта,
  срабатывания governor.
